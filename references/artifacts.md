# Artifact production

The discussion file is a working record, not a final design. When requested and sufficiently settled, synthesize one or more of:

- Design: problem, goals/non-goals, current system, proposed solution, alternatives, risks, validation, rollout.
- Requirements: observable behavior, constraints, acceptance criteria, exclusions.
- ADR: context, decision, status, alternatives, consequences, revisit triggers.
- Tickets: independently verifiable tasks, dependencies, test expectations, acceptance criteria.

Only accepted decisions should be described as settled. Mark unresolved questions and assumptions explicitly. Ask permission before writing new artifacts. Do not launch implementation merely because a design is approved.
