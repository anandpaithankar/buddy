# Checkpoint protocol

At a natural pause, present a short proposed update containing only material changes:

**Proposed checkpoint — [topic]**
- Established: ...
- Options/assumptions revised: ...
- Proposed decision (if any): ...
- Still open: ...

Ask whether to **record, revise, or keep exploring**. Do not write until the user approves the specific update. A user's acceptance of a technical suggestion is not automatically approval to persist an unrelated file change.

When approved, update the smallest relevant section of the existing Markdown file. Prefer editing over appending repeated summaries. Preserve superseded decisions with reason and date when useful. Do not overwrite unrelated user edits. If a file is missing, offer to create it from the template. If filesystem writes are unavailable, return the approved Markdown text.

A session handoff should record current focus, accepted decisions, material unknowns, and next discussion point. Do not invent a checkpoint on every turn.
